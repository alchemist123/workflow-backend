# {{ workflow_name }} — ADK graph workflow, served over A2A

Generated by the no-code platform. This directory is a complete, self-contained
Python project with no dependency on the platform backend.

The workflow is a [Google ADK graph](https://adk.dev/graphs/) exposed as an
[A2A](https://a2a-protocol.org/) agent: other agents discover it from its agent
card and call it over JSON-RPC.

## Quick start

```bash
cp .env.example .env      # then fill in real values
docker compose up --build -d

curl http://localhost:8080/health
curl http://localhost:8080/.well-known/agent-card.json
```

Or without Docker:

```bash
pip install -r requirements.txt
uvicorn main:a2a_app --host 0.0.0.0 --port 8080
```

To run the tests as well, install `requirements-dev.txt` instead.

## Calling the workflow

Two invocation modes, both on `POST /`. They differ only in
`configuration.blocking`, and both return the same result.

### Message-based — wait for the answer

```bash
curl -s -X POST http://localhost:8080/ \
  -H 'Content-Type: application/json' \
  -d '{
        "jsonrpc": "2.0",
        "id": "1",
        "method": "message/send",
        "params": {
          "message": {
            "role": "user",
            "kind": "message",
            "messageId": "m1",
            "parts": [{"kind": "text", "text": "{\"text\": \"hello\"}"}]
          },
          "configuration": {"blocking": true}
        }
      }'
```

The reply is a Task with `status.state = "completed"`; the workflow's result is
the JSON text in `result.artifacts[0].parts[0].text`.

### Task-based — submit now, poll later

Submit without blocking and keep the returned task id:

```bash
curl -s -X POST http://localhost:8080/ \
  -H 'Content-Type: application/json' \
  -d '{
        "jsonrpc": "2.0", "id": "1", "method": "message/send",
        "params": {
          "message": {
            "role": "user", "kind": "message", "messageId": "m2",
            "parts": [{"kind": "text", "text": "{\"text\": \"hello\"}"}]
          },
          "configuration": {"blocking": false}
        }
      }'
# -> {"result": {"id": "<task-id>", "status": {"state": "submitted"}, ...}}
```

Then poll that id until the state is terminal (`completed`, `failed` or
`canceled`):

```bash
curl -s -X POST http://localhost:8080/ \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":"2","method":"tasks/get","params":{"id":"<task-id>"}}'
```

Use this mode for a workflow that takes longer than a caller should hold a
connection open for.

> Polling defaults to an in-memory task store, so a task id is only valid in the
> process that accepted it — a poll routed elsewhere returns not-found, and a
> restart drops in-flight tasks. Set `TASK_STORE_DSN` to persist tasks.

The payload inside `parts[].text` should be JSON matching `PAYLOAD_SCHEMA` in
`nodes/a2a_start.py`. Plain prose is also accepted and arrives as
`{"text": "..."}`.

## Endpoints

| Endpoint | Purpose |
|---|---|
| `POST /` | A2A JSON-RPC: `message/send`, `tasks/get`, `tasks/cancel`, … |
| `GET /.well-known/agent-card.json` | Agent card — how other agents discover this one |
| `GET /.well-known/agent.json` | Same card, for older A2A clients |
| `GET /health` | Liveness probe |
| `GET /graph` | The compiled graph, for debugging a running container |

## Layout

| Path | What it is |
|---|---|
| `main.py` | Entry point: builds the served app |
| `agent.py` | **The graph.** The edge list is the whole topology |
| `nodes/registry.py` | The node register: every node by name, plus canvas ids |
| `nodes/<node>.py` | One file per canvas node |
| `nodes/base.py` | The node authoring contract |
| `core/config.py` | Settings, from the environment or `.env` |
| `core/agent_card.py` | The advertised agent card |
| `core/a2a_app.py` | App assembly: A2A routes, health, auth, task store |
| `core/state.py` | Input coercion and workflow-state helpers |
| `tools/` | MCP servers, remote A2A agents and inline functions as agent tools |
| `tests/` | Graph, per-node and A2A round-trip tests |
| `graph.json` | The compiled graph plan |
| `requirements.txt` | Runtime dependencies (what the image installs) |
| `requirements-dev.txt` | Runtime plus test dependencies |

## Tests

```bash
pytest
```

The suite runs offline — no model, no network — and covers three things:

- `tests/test_graph.py` — the graph builds and satisfies ADK's structural rules
  (one entry, exactly one terminal node, no duplicate edges), and routes correctly
- `tests/test_nodes.py` — each node against stub input, plus the core helpers
- `tests/test_a2a.py` — the agent card, blocking send, non-blocking send,
  `tasks/get` polling, and that both modes agree

## Editing this package

Node behaviour lives in `nodes/<node>.py` and the topology in `agent.py`, so
both are editable by hand. Re-packaging from the platform overwrites them —
change the canvas instead if you want the edit to survive.

Two ADK rules are load-bearing, and breaking either fails at run time rather
than at import:

1. **Exactly one terminal node.** Fan-out is fine mid-graph, but every path must
   reconverge, or the run fails with *multiple terminal nodes produced output*.
2. **The terminal node must emit content.** `nodes/base.py::terminal_event`
   does this. An event carrying only `output` produces no artifact and the A2A
   task stays `working` forever.

## Deploying to Cloud Run

```bash
gcloud run deploy {{ workflow_slug }} \
  --source . \
  --region "${VERTEX_AI_LOCATION:-us-central1}" \
  --set-env-vars "AGENT_NAME=${AGENT_NAME},GOOGLE_CLOUD_PROJECT=${GOOGLE_CLOUD_PROJECT}"
```

Then set `CLOUD_RUN_URL` to the service URL and redeploy: it becomes the agent
card's `url`, which is how other agents find this one. Put `A2A_AUTH_TOKEN` and
any credentials in Secret Manager rather than in `--set-env-vars`.
