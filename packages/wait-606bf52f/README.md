# Wait — ADK graph workflow, served over A2A

Generated by the no-code platform from workflow version `606bf52f-c1e6-4008-aa19-5df12fb93c41`.
This directory is a complete, self-contained Python project with no dependency
on the platform backend.

The workflow is a [Google ADK graph](https://adk.dev/graphs/) exposed as an
[A2A](https://a2a-protocol.org/) agent: other agents discover it from its agent
card and call it over JSON-RPC.

## The graph

```
START
  -> a2a_start  [A2A_START]
  ->   -> n_parallel_fork_4  [PARALLEL_FORK]
  ->   ->   -> n_wait_7  [WAIT]
  ->   ->   ->   -> n_transform_1  [TRANSFORM]
  ->   ->   ->   ->   -> n_merge_5  [MERGE]
  ->   ->   ->   ->   ->   -> n_end_3  [END]
  ->   ->   -> n_wait_2  [WAIT]
  ->   ->   ->   -> n_transform_6  [TRANSFORM]
  ->   ->   ->   ->   -> n_merge_5  (loops back)
```

| Node | Type | Canvas node |
|---|---|---|
| `a2a_start` | A2A_START | Start |
| `n_end_3` | END | End |
| `n_merge_5` | MERGE | Join |
| `n_parallel_fork_4` | PARALLEL_FORK | Split |
| `n_transform_1` | TRANSFORM | Check Status |
| `n_transform_6` | TRANSFORM | Send Receipt |
| `n_wait_2` | WAIT | Rate limit |
| `n_wait_7` | WAIT | Let it settle |

## Quick start

```bash
cp .env.example .env      # then fill in real values
docker compose up --build -d

curl http://localhost:8080/health
curl http://localhost:8080/.well-known/agent-card.json
```

Or without Docker:

```bash
pip install -r requirements.txt
uvicorn main:a2a_app --host 0.0.0.0 --port 8080
```

To run the tests as well, install `requirements-dev.txt` instead.

## Calling the workflow

Two invocation modes, both on `POST /`. They differ only in
`configuration.blocking`, and both return the same result.

The payload goes inside `parts[].text` as JSON:

```json
{
  "order_id": ""
}
```

### Message-based — wait for the answer

```bash
curl -s -X POST http://localhost:8080/ \
  -H 'Content-Type: application/json' \
  -d '{
        "jsonrpc": "2.0",
        "id": "1",
        "method": "message/send",
        "params": {
          "message": {
            "role": "user",
            "kind": "message",
            "messageId": "m1",
            "parts": [{"kind": "text", "text": "{\"order_id\": \"\"}"}]
          },
          "configuration": {"blocking": true}
        }
      }'
```

The reply is a Task with `status.state = "completed"`; the workflow's result is
the JSON text in `result.artifacts[0].parts[0].text`.

### Task-based — submit now, poll later

Submit without blocking and keep the returned task id:

```bash
curl -s -X POST http://localhost:8080/ \
  -H 'Content-Type: application/json' \
  -d '{
        "jsonrpc": "2.0", "id": "1", "method": "message/send",
        "params": {
          "message": {
            "role": "user", "kind": "message", "messageId": "m2",
            "parts": [{"kind": "text", "text": "{\"order_id\": \"\"}"}]
          },
          "configuration": {"blocking": false}
        }
      }'
# -> {"result": {"id": "<task-id>", "status": {"state": "submitted"}, ...}}
```

Then poll that id until the state is terminal (`completed`, `failed` or
`canceled`):

```bash
curl -s -X POST http://localhost:8080/ \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":"2","method":"tasks/get","params":{"id":"<task-id>"}}'
```

Use this mode for a workflow that takes longer than a caller should hold a
connection open for.

> Polling defaults to an in-memory task store, so a task id is only valid in the
> process that accepted it — a poll routed elsewhere returns not-found, and a
> restart drops in-flight tasks. Set `TASK_STORE_DSN` to persist tasks.

The expected payload is documented as `PAYLOAD_SCHEMA` in
`nodes/a2a_start.py`. Plain prose is also accepted and arrives as
`{"text": "..."}`.

## Environment

- `PORT` — Port the agent listens on.
- `AGENT_NAME` **(required)** — Advertised agent name.
- `AGENT_DESCRIPTION` **(required)** — Advertised description.
- `AGENT_VERSION` **(required)** — Advertised version.
- `CLOUD_RUN_URL` — Public base URL; becomes the agent card's url. Blank falls back to localhost.
- `A2A_AUTH_TOKEN` — When set, callers must send this as a bearer token and the agent card advertises that it is required.
- `TASK_STORE_DSN` — SQLAlchemy async DSN. Blank uses an in-memory store, so tasks/get only works within one process and in-flight tasks are lost on restart.

## Editing this package

Node behaviour lives in `nodes/<node>.py` and the topology in `agent.py`, so
both are editable by hand. Re-packaging from the platform overwrites them —
change the canvas instead if you want the edit to survive.

Two ADK rules are load-bearing, and breaking either fails at run time rather
than at import:

1. **Exactly one terminal node.** Fan-out is fine mid-graph, but every path must
   reconverge, or the run fails with *multiple terminal nodes produced output*.
2. **The terminal node must emit content.** `nodes/base.py::terminal_event`
   does this. An event carrying only `output` produces no artifact and the A2A
   task stays `working` forever.

## Credentials

Anything the canvas configured as a credential — API keys, service account
keys, bearer tokens, MCP URLs that carry basic auth — is **not** in this
repository. Each one became an environment variable, and its value is in `.env`,
which `.gitignore` and `.dockerignore` both exclude. The committed
`.env.example` names every variable and says which node needs it, with
credentials left blank.

That matters because this directory is a git repository and the agent serves its
own `graph.json` from `GET /graph`. A credential in either would be exposed
twice over.

For a real deployment, put them in Secret Manager and mount them as environment
variables rather than shipping a populated `.env`.

## Authentication

Set `A2A_AUTH_TOKEN` and this agent requires `Authorization: Bearer <token>` on
every JSON-RPC call, and its agent card advertises the requirement so callers
discover it rather than finding out from a 401:

```json
"security": [{"bearerAuth": []}],
"securitySchemes": {"bearerAuth": {"type": "http", "scheme": "bearer"}}
```

The agent card and `/health` stay public — the card is how a caller learns a
token is needed, and Cloud Run's probe cannot send one.

Leave `A2A_AUTH_TOKEN` blank and the agent accepts unauthenticated calls, which
it logs a warning about at start-up. That is fine behind a private network or
Cloud Run's own IAM, and not fine on the open internet.

## Task persistence

By default tasks live in memory. That is fine for one local process, but on
Cloud Run it means a `tasks/get` routed to a different instance than the one
that accepted the message returns not-found, and a restart drops every in-flight
task.

Set `TASK_STORE_DSN` to a SQLAlchemy async DSN and tasks are persisted instead,
so polling works across instances and across restarts:

```
TASK_STORE_DSN=postgresql+asyncpg://user:pass@host:5432/tasks
```

The table is created on first use. A DSN the driver cannot parse fails at
start-up with a message naming the variable, rather than quietly falling back —
persistence you asked for and did not get is worse than a clear error.

## Deploying to Cloud Run

```bash
gcloud run deploy wait-606bf52f \
  --source . \
  --region "${VERTEX_AI_LOCATION:-us-central1}"
```

The container reads `PORT` at start-up, which is what Cloud Run injects, and
runs as a non-root user.

Then set `CLOUD_RUN_URL` to the service URL and redeploy: it becomes the agent
card's `url`, which is how other agents find this one. Note that `AGENT_NAME`
must be a valid Python identifier — ADK validates a workflow's name as a node
name, so a space or a hyphen breaks the graph at import.
